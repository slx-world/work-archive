钉钉记录逐条平铺使用说明
版本 2.0.0  日期 2026-10-22

用途
将每条有效原始记录的 fields 展开为一个包含七个固定字段的字典。
result 为列表；不按公司或店铺分组，不合并记录，不去重。
生产代码不导入模块，不打印数据，不发网络请求，不读写文件，不修改输入。
仓库数据为虚构示例，真实运行中的密码及其他非空字符串原样保留。

用法一 直接执行式节点
在 Python 节点添加输入参数 iPaas_result，绑定上一步获取多行记录返回的列表。
将 dingtalk_node.py 全文粘贴到节点，配置输出变量 result 为列表或通用 JSON。
该文件末尾已经包含：result = transform_records(iPaas_result)。
上一步结果命名为 iPaas_result，不代表代码节点自动具有同名变量，仍需输入映射。

用法二 函数式节点
使用 dingtalk_transform.py，main(iPaas_result) 返回 {"result": [...]}。
平台若规定其他函数名、参数签名、上下文对象或返回方式，仅适配入口。
transform_records(records) 是主函数；transform(records) 是同等行为的兼容入口。
两种入口选择一种，不要在函数式节点中附加未绑定的顶层变量调用。

对象包装输入
默认输入必须是列表，不接收打印后的字符串，不猜测 data 或 records 字段。
仅当实际输入为 {"data": {"records": [...]}} 时，可将直接执行式脚本末尾替换为：
records = extract_records(iPaas_result, ["data", "records"])
result = transform_records(records)
上述字段路径只是示例，不代表钉钉所有接口采用相同包装。

输入输出字段
fields.公司名 -> 公司名
fields.企业用户名 -> 企业用户名
fields.企业密码 -> 企业密码
fields.店铺 -> 店铺
fields.站点[*].name -> 站点列表
fields.运营负责人[*].unionId -> unionId 列表
fields.运营负责人[*].name -> name 列表
创建人、修改人、时间戳、记录 id、站点 id 不进入输出。
负责人只来自运营负责人，不从创建人或修改人读取。

处理规则
fields 缺失、null 或 {} 时跳过。
非空 fields 的公司名必须是非空白字符串，否则报错。
用户名和密码缺失或 null 时输出空字符串；非空值原样保留，不裁剪字符。
店铺缺失、null 或空字符串时使用公司名；只有空白字符的店铺名报错。
站点和运营负责人缺失或 null 时按空列表处理。
站点和人员列表保留原顺序和重复项；缺失的 name、unionId 使用空字符串占位。
空人员对象也保留对应的两个空字符串，使人员列表与原始列表位置对应。
unionId[i] 与 name[i] 表示同一位负责人，两个列表长度相等。
相同公司或店铺、完全重复的原始记录也分别输出；每条输出字典与列表互相独立。
非对象记录、非对象 fields、非列表站点或人员、非法字符串类型会报错，不静默丢弃。
报错信息包含 records 下标及字段位置，不回显密码等输入值。

示例数量
仓库示例有 10 条输入：7 条基础有效记录、1 条重复有效记录、2 条空记录。
因此输出 8 条记录，第 1 条与第 8 条内容相同，但分别保留。
用户提供的业务数据含 7 条有效记录，转换后对应 7 条记录。
result[0] 是第一条记录；result[0]["站点"] 是第一条记录的站点列表。
JSON 使用 UTF-8、双引号和 null。Python 列表对象无需再次做字符串解析。

从旧版迁移
旧版按公司账号分组，店铺名为动态键；新版店铺为固定字段的值。
将 result[i][店铺名]["站点"] 改为 result[i]["站点"]。
店铺名读取 result[i]["店铺"]，人员读取 result[i]["unionId"] 和 result[i]["name"]。
下游不得假设公司名或店铺名唯一，也不应再用“唯一店铺数”判断输出条数。
旧版代码可在 Git 历史查看，当前目录全部使用 2.0.0 的逐条规则。

分页和接入边界
函数只转换传入的记录，不调用接口、不拉取分页、不跨节点保存状态。
需要全部记录时，先收集所有页面并按需要的顺序拼接列表，再转换。
重复页面中的有效记录也会保留，是否过滤重复页面由上游决定。
节点输入输出类型、输出大小及执行时间限制以实际运行平台为准。
本地测试不等于已在用户钉钉环境内联调，仍需确认输入映射和输出声明。

验证与排错
在仓库根目录运行：python -m unittest discover -s projects/dingtalk-record-transform -v
NameError iPaas_result 未定义：检查代码节点输入映射。
记录数据必须是列表：绑定真正的记录列表，或显式提取包装对象中的路径。
字段类型错误：根据错误中的 records 下标及字段位置修复输入。
没有结果输出：检查平台要求的函数入口和 result 输出声明。
输出多于店铺数量：同店铺的多条原始记录分别输出，这是本版约定。
完整测试结果见验收结果.txt；JSON Schema 供结构核对，列表等长关系由代码额外保证。

推送前脱敏
归档到 GitHub 的账号、密码、公司和人员标识均使用虚构示例，不提交业务原文。
运行转换本身不会对业务密码脱敏，脱敏要求作用于待归档的示例与文件。
提交前审阅文本及 DOCX 正文和元数据，执行暂存区及待推送历史扫描。
扫描只覆盖定义过的模式，人工仍需复核上下文和无法自动读取的内容。
