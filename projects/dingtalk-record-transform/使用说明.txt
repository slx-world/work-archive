钉钉多行记录转换交付说明
版本 1.0.0  日期 2026-10-22

用途
将用户提供结构的钉钉记录列表转换为按公司和账号分组、按店铺组织的列表。
生产转换代码不导入模块，不打印数据、不发网络请求、不修改输入。
本包示例全部使用虚构公司、账号、密码和 unionId。

文件清单

dingtalk_transform.py      转换函数与 main 函数入口，适合导入或函数式节点
使用说明.docx              输入绑定、数据格式、规则、错误和验收说明

examples/output.json       transform 的预期返回列表
examples/wrapped_input.json  对象包装示例，仅说明显式字段路径用法
examples/main_output.json   main 的预期返回对象

用法一 直接执行式代码节点
1 将输入变量命名为 iPaas_result，绑定获取多行记录步骤的记录列表。
2 将 dingtalk_node.py 全文粘贴到 Python 代码节点。
3 配置输出变量 result，类型选择数组或列表；若平台仅支持通用 JSON，使用 JSON。
4 后续节点引用代码节点的 result 输出。
仅给上一步结果命名，不代表代码节点会自动获得同名变量，仍需配置输入映射。

用法二 函数式代码节点
使用 dingtalk_transform.py；其中 main(iPaas_result) 返回 {"result": [...]}。
若平台要求其他函数名、参数签名、上下文对象或返回方式，仅适配入口。
示例中参数名及返回封装不是对所有钉钉平台的统一约定。
不要同时执行直接执行式末尾调用和函数式入口。

对象包装输入
转换函数默认只接收列表，不自动猜测 data、records、result 等字段。
如果实际数据确实为 {"data": {"records": [...]}}，在节点末尾使用：
records = extract_records(iPaas_result, ["data", "records"])
result = transform(records)
这两行替换 dingtalk_node.py 最后的 result = transform(iPaas_result)。
wrapped_input.json 的路径仅为示例，不代表用户接口固定采用该结构。

字段映射
fields.公司名 -> 输出的公司名
fields.企业用户名 -> 输出的企业用户名
fields.企业密码 -> 输出的企业密码
fields.店铺 -> 输出对象的动态键；缺失、null 或空字符串时使用公司名
fields.站点[*].name -> 店铺下的站点列表
fields.运营负责人[*].unionId -> 店铺下的 unionId 列表
fields.运营负责人[*].name -> 店铺下的 name 列表
id、createdBy、lastModifiedBy、时间戳及站点 id 不进入输出。
负责人只从运营负责人读取，不从创建人或修改人读取。

合并和缺失值规则
按 公司名、企业用户名、企业密码 三项的精确值分组。
同公司不同用户名或不同密码产生不同输出元素，不擅自选择最新密码。
同组同店铺合并；站点按名称去重，人员按 unionId 与 name 的组合去重。
同一 unionId 若姓名不同，会保留两组对应值，避免猜测哪一个姓名更新。
公司、店铺、站点及人员保持首次出现顺序；不裁剪或改写非空字符串。
密码的空格、换行及特殊字符原样保留；代码不会修复打印文本中的格式损坏。
用户名、密码缺失或 null 输出空字符串；生产流程需要凭据时请在下游校验非空。
站点、运营负责人缺失或 null 视为空列表；人员两个字段均为空时跳过。
只有姓名或只有 unionId 的人员仍保留，另一列表在对应位置填空字符串。
fields 缺失、null 或 {} 的记录跳过；非空 fields 的公司名不能为空白。
动态店铺名不能为 公司名、企业用户名、企业密码，否则明确报错。
同公司不同账号场景下，下游不能仅用公司名作为唯一键，应按账号进一步匹配。

数据格式
result 是列表，不是单个公司对象。result[0] 才是第一组公司和账号。
Python 对象使用列表和字典，JSON 文件使用 UTF-8、双引号和 null。
不需要 eval，不需要对原始列表做字符串替换，也不需要 ast.literal_eval。
Python 中字符串可能显示为单引号；这不会改变数据本身。
unionId[i] 和 name[i] 始终表示同一个负责人，两个列表长度相等。
JSON Schema 用于结构核对；公司名非空白、动态键冲突和两列表等长还需代码校验。

常见错误
NameError iPaas_result 未定义：检查代码节点输入映射及变量名。
记录数据必须是列表：当前传入的是对象或文本；先绑定列表或显式提取字段路径。
records[n].fields 必须是对象：输入结构不符合约定，不要自动当成空记录丢弃。
公司名不能为空：补齐非空记录的公司名，或在上游明确过滤该记录。
店铺与输出保留字段重名：修改上游店铺名；本格式无法同时承载同名元数据键和店铺键。
无输出：检查平台是否要求 main 返回值，或是否需要声明 result 为节点输出。
结果条数少于输入：空记录被跳过，相同公司账号的多店铺、重复记录被合并。

分页与接入
函数只转换传入的数据，不调用接口、不自动拉取分页、不跨节点保存状态。
若上游只返回一页，先取得所有所需页面并拼接列表，再调用 transform。
不要分别转换每页后简单拼接结果，否则同公司同店铺可能跨页重复。
平台可能限制输出大小和执行时间，请按实际节点限制核对。
代码按用户提供的返回结构设计，本地验证不等于已在用户钉钉环境联调。

本地验收
在本目录用 Python 3.8 或更新版本运行：python -m unittest -v
仅测试文件使用 Python 标准库；实际转换和节点代码不需要导入任何模块。
示例共 10 条输入，其中 1 条重复、2 条空记录；输出 5 组公司账号、7 家店铺。
输入和输出 JSON 示例可逐项对比；验收结果另见 验收结果.txt。
