# 日常工作资料归档流程

为每项工作创建 `projects/任务名称/`，保存可复用代码、虚构示例、字段说明、验证结果和操作文档。首次归档项目使用 `projects/dingtalk-record-transform/`。

将真实业务数据保留在 Git 忽略的本地目录中，只将必要结构转换为虚构示例。密码与标识替换后，应重新执行测试，确认脱敏未破坏字段对应关系。

归档时记录用途、输入输出、运行方式、依赖、验证结果和已知限制。文档与代码应同时更新。每次提交前审阅差异，运行暂存区扫描；每次推送前检查历史，再推送。

外部原始附件不自动归档。需要保存图片、PDF 或其他无法自动扫描的资料时，先完成实际脱敏，再按 policy/REDACTION.md 记录人工复核。
