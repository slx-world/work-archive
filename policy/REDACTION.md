# 敏感信息脱敏规则

每次推送前检查所有新增提交，不只检查最终文件。仓库即使为私有，也使用脱敏后的示例资料。

## 替换规则

| 数据 | 归档形式 |
| --- | --- |
| 密码和访问密钥 | 使用 DemoOnly 或 REDACTED 前缀的虚构值，保留测试需要的特殊字符 |
| 业务账号和企业用户名 | demo_account 等虚构账号 |
| 人员 unionId 和其他标识 | demo_u01 等稳定占位符，同一人物使用同一占位符 |
| 公司和人员姓名 | 示例公司、负责人甲等虚构名称 |
| 手机号和证件号 | 使用带 REDACTED 前缀的说明，避免生成看似真实的号码 |
| 邮箱和网络地址 | 使用 example.com、example.org 等示例地址 |
| 内部路径和服务器地址 | 使用通用相对路径或说明性占位符 |
| Word 文档 | 正文和元数据均检查，删除批注、修订及未脱敏嵌入内容 |

## 扫描方式

`privacy_gate.py` 使用 Python 标准库，识别常见密钥、令牌、手机号、身份证号、邮箱、URL 内嵌凭据、钉钉真实 unionId 形态，以及敏感字段中的非示例值。JSON 中的公司及人员字段也要求使用示例值。扫描仅报告路径和规则名，不打印秘密内容。

文本必须使用 UTF-8。脚本检查 DOCX 中的 XML 和属性；包含图片或嵌入对象的 DOCX 会被阻止，需先移除或另行转成可审阅的脱敏资料。不接收 ZIP 归档，避免隐藏未审阅内容。

对于 PNG、PDF 等无法自动确认内容的二进制文件，先完成实际脱敏和人工复核，再在 manual-reviews.json 记录文件相对路径、SHA256、redacted 为 true、reviewed_by 和 reviewed_at。文件变化后哈希失效，必须重新复核。人工记录只豁免不可读二进制，不豁免扫描发现的文本秘密。

示例结构如下，其中哈希必须替换为实际脱敏文件的哈希，复核人填写不含个人隐私的代号：

```json
{
  "docs/example-redacted.pdf": {
    "sha256": "REPLACE_WITH_ACTUAL_SHA256",
    "redacted": true,
    "reviewed_by": "reviewer-01",
    "reviewed_at": "2026-10-22"
  }
}
```

人工复核记录是工作记录，不是加密证明。自动检查没有覆盖的商业信息、图片像素及上下文身份关联仍需人工确认。不得为了上传真实秘密而加入复核记录。

## 上传边界

本地 hook 在 Git 推送前运行；新克隆必须手动启用。GitHub 网页、API 和未启用 hook 的客户端不会自动执行本地检查。使用这些方式前，必须先对待上传的相同内容运行扫描和人工审阅。GitHub Actions 在推送后执行，不能阻止资料首次上传。

若敏感信息已进入 Git 历史，应先撤销或轮换真实凭据，再清理相关历史。只删除当前文件不能消除早先提交中的内容。
